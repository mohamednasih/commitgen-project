From diff to history

A deliberate six-step workflow.

CommitGen uses Git’s staging area as the source of truth, generates both parts of the message, and asks before committing. Interactive mode adds the full editing loop when you need it.

Validate context

The CLI checks for GEMINI_API_KEY, confirms the current directory belongs to a Git worktree, and stops early with a clear error if either requirement is missing.

Read staged work

It runs git diff --cached and git diff --cached --name-only. Unstaged files are intentionally excluded, so the suggestion describes only what the next commit will contain.

Generate a title

A diff summary and fair sample from every staged file are sent to Gemini with strict instructions: one line, Conventional Commit syntax, imperative language, and fewer than 70 characters.

Generate a description

Gemini receives the accepted title, changed files, and staged diff, then returns concise bullet points describing what changed and why.

Confirm the commit

The default path displays the generated message and asks you to commit, cancel, regenerate, or edit it. git commit -m runs only after you answer yes.

Review when needed

Run commitgen --interactive or commitgen -i to restore the complete accept, regenerate, edit, skip, and quit workflow. Optional notes end when you type EOF on its own line.

Architecture

Small surface. Clear boundaries.

The Go port divides interaction, Git operations, prompt construction, editing, and remote generation into focused components. The standard library provides everything else.

01 / entry

Process lifecycle

The command entry point wires streams, handles Ctrl+C, starts the application, and maps failures to a non-zero exit.

02 / orchestration

Interactive state

The application coordinates default confirmation plus interactive review, regeneration, editing, cancellation, and final commit.

03 / local

Git boundary

Repository checks, staged diffs, changed filenames, and commit creation are isolated behind direct Git subprocess calls.

04 / intelligence

Prompt contract

Editable title and description templates constrain format while preserving filenames and relevant diff context. Your versions are embedded when the binary is built.

05 / network

Gemini REST client

A 60-second HTTP client sends JSON directly to the Gemini generateContent endpoint using the API-key header.

06 / human

Editor bridge

Temporary files connect generated text to your editor. Comment lines are removed and the temporary file is deleted afterward.

Installation

Build it once. Run it without Go.

The installer prefers a local Go 1.22+ toolchain. If Go is absent but Docker is available, it uses the official Go image and cross-compiles for your host OS and architecture.

Behavior & configuration

Predictable defaults, visible failure modes.

The interface is intentionally narrow. Two environment variables control remote generation; every important local assumption is checked before the commit is created.

Environment

Configuration stays outside the binary and repository.

GEMINI_API_KEY
Required credential sent in the x-goog-api-key request header. CommitGen does not persist it.
COMMITGEN_MODEL
Optional model override. Defaults to gemini-3.1-flash-lite.
EDITOR
Optional editor command. Defaults to nano on Unix-like systems or notepad on Windows.
GOBIN
Optional installation directory used by install.sh.

Resilience

Generation errors do not hide what happened.

HTTP timeout
Gemini calls stop after 60 seconds instead of hanging indefinitely.
Transient errors
Rate limits, timeouts, and server errors are retried three times with visible 1, 2, and 4 second backoff notices.
Empty response
Aborts the operation without creating a commit instead of proposing placeholder content.
Git failure
The commit error and Git output are surfaced; the application exits with status 1.

Privacy boundary

Know what leaves your machine.

CommitGen sends the staged filenames and up to 8,000 characters of the staged diff to Google Gemini. Your unstaged changes are not included by the Git commands used.

Review staged content before running the tool. Do not stage credentials, private keys, customer data, or proprietary material that you are not permitted to send to an external AI service.

Common questions

Before you run it.

Does CommitGen ask before creating the commit?

Yes. Running commitgen generates and displays the title and description, then asks you to commit (y), cancel (n), regenerate both (r), or edit the complete message (e). Use --interactive or -i for separate title and description controls.

Does the destination machine need Go or Docker?

No. A compiled CommitGen binary is self-contained. The destination needs only a compatible operating system and CPU, Git in its PATH, network access, and a Gemini API key. Go or Docker is required only on the machine building from source.

Can CommitGen commit unstaged changes?

No. It reads Git’s cached diff, which represents the staging area, and the eventual git commit also commits staged content. This makes git add your explicit boundary.

What happens when Gemini is unavailable?

Retryable failures receive three attempts with backoff. If Gemini still fails—or returns no usable text—the entire operation stops with a non-zero exit and no commit is created.

Why use Go for this project?

Go produces compact, cross-platform executables and provides HTTP, JSON, subprocess, signal, and terminal primitives in its standard library. That removes Python interpreter and package-management requirements from end users.
